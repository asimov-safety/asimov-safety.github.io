Implementation patterns

Find your
architecture.

Different frameworks expose different hooks. Asimov reduces them to the same six deployment surfaces: action, authority, resource truth, lifecycle, supervision, and evidence.

01

OpenAI Agents

Use the SDK as the action/orchestration layer; keep authority and effect truth outside it.

Runner/application entry points drive test actions. Tool and handoff traces supply orchestration evidence. IAM or a policy gateway supplies real grants/revocation. The protected database/API/cloud resource supplies the independent oracle. A separate supervisor or infrastructure control plane supplies A3+ intervention.

Driver · tracing · external IAM · resource oracle · supervisor
02

Claude Agent SDK

Use hooks and permissions as instrumentation; enforce consequential authority outside the agent runtime.

SDK sessions drive actions. Tool-use hooks provide proposal and dispatch evidence. IAM, OS identities, cloud policy, or a separate gateway supplies the real authority boundary. Observe the destination resource independently and keep A3 supervision outside the generated-code privilege domain.

SDK · hooks · permissions · external authority
03

Google ADK

Callbacks expose the workflow; cloud identity and resource state establish control and truth.

ADK runner/workflows drive actions. Agent/model/tool callbacks supply lifecycle and mediation hooks. Sessions/events preserve orchestration state. Google Cloud service accounts, sandbox/runtime controls, and the target resource supply the independent authority and observation surfaces.

ADK · callbacks · service account · Cloud audit
04

LangGraph / LangChain

Treat graph state as orchestration evidence—not proof of an external effect.

Graph invocation and tool nodes drive actions. Checkpoints and callbacks track lifecycle. An external policy/IAM layer enforces authority. Verify effects at the database, API, queue, or cloud resource. Use a separate supervisor service for A3 and above.

Graph · checkpoint · policy gateway · external oracle
05

CrewAI / multi-agent teams

Role prompts describe behavior; authenticated principals control authority.

Crew/task execution drives actions and delegation. Agent/task graphs provide lineage. Tools and MCP endpoints are enumerated as consequential paths. External IAM mediates permissions, and the destination resource independently establishes what actually occurred.

Crew graph · tool paths · authenticated authority · resource truth
06

Local Python / Ollama

Own the whole stack, then separate the parts that must remain independent.

The Python orchestrator is the driver. Put consequential tools behind an enforceable dispatcher or OS/service boundary. Use separate identities/processes for resource observation and supervision. For A3, the only stop latch cannot live inside the same unrestricted process running generated code.

Python · tool boundary · OS identity · independent supervisor
07

Kubernetes

Use workload identity and infrastructure policy as the enforcement substrate.

Service accounts/workload identity bind the actor. NetworkPolicy, service mesh, admission/policy gateways, and cloud IAM enforce capability boundaries. The Kubernetes API supplies lifecycle control. Resource APIs and audit systems independently verify effects. A4 exercises partitions and common-mode infrastructure failures.

Workload identity · policy · K8s lifecycle · audit
08

AWS / Azure / Google Cloud

Map grants and revocation onto native identity controls; measure effectiveness at the resource.

Use IAM roles, managed/workload identities, short-lived credentials, resource policies, and native audit logs. Revocation timing is measured when the protected service stops accepting the authority—not when the control-plane API merely acknowledges the change.

IAM · short-lived authority · resource policy · cloud audit
09

Databases, APIs, filesystems & queues

The destination itself is usually the best oracle.

For PostgreSQL use a separate assessor/audit identity. For HTTP APIs query authoritative server state. For filesystems inspect from a distinct process or identity. For queues track enqueue, admission, execution, cancellation, retries, and orphaned work. Do not use the model's success text as evidence of effect.

Authoritative state · independent read · lifecycle evidence

Framework hooks tell you what the agent tried. Resource oracles tell you what actually happened.
