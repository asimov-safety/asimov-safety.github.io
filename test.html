Connect your stack

Start with what you already use.

You do not need to translate every framework API into Asimov by hand. Studio's Adapter Assistant starts from the runtime, cloud, authority system, and protected resources you already have.

Install Asimov

The current reference implementation and Studio require Python 3.10+. Asimov Core itself remains language-neutral.

python3 -m pip install "https://github.com/asimov-safety/asimov/archive/refs/heads/main.zip"

Open Adapter Assistant

Launch Studio and choose the real runtime architecture: OpenAI Agents API vs SDK vs custom Responses loop; Claude Managed Agents vs Agent SDK vs custom Messages loop; Google ADK; Microsoft Agent Framework; LangGraph; CrewAI; or a custom/local stack.

asimov studio

Then choose hosting, authority, protected resources, evidence sources, and MCP integrations. Studio shows the six-surface mapping before generating anything.

Generate a conservative starter

Studio writes adapter.py, a stack-specific README, and asimov-adapter.json. The starter deliberately claims zero Asimov capabilities until you connect real controls and independent evidence.

asimov adapter-scaffold --runtime openai-agents-api --output ./asimov-adapter

Wire the real controls, then run readiness

Framework hooks can tell Asimov what the agent attempted. Real authority, resource, lifecycle, supervision, and evidence surfaces determine whether the requested assurance level is actually testable.

asimov doctor --level A5

End-to-end assessment

Prepare the human work before the machine work.

A real Asimov assessment is staged. The adapter is target-specific; everything after it is generic. A5 is cumulative, so one A5 run covers A1 through A5 and the report resolves each profile separately.

1 · Prepare

Generate the scope, mandatory preconditions, every HYBRID / REVIEW_REQUIRED checklist, independence requirements, and the profile-specific signing plan before probes run.

asimov prepare-assessment \
  --adapter ./my_adapter.py:MyAdapter \
  --adapter-kwargs '{}' \
  --level A5 \
  --assessor "Your Name or Assessment Team" \
  --subject-organization "Deployment operator" \
  --assessor-organization "Assessment organization" \
  --mode self_assessment \
  --output ./assessment

Read REVIEW-CHECKLIST.md, verification-plan.json, and scope.json, then acknowledge the obligations in one command. Acknowledgement is not a PASS and does not pretend that an independent A5 review already happened.

asimov acknowledge-assessment ./assessment \
  --reviewer "Your Name" \
  --reviewer-role "System owner / self-assessor"

2 · Execute

The technical suite refuses to start if required pre-run human/review obligations have not been acknowledged.

asimov run-assessment ./assessment \
  --adapter ./my_adapter.py:MyAdapter \
  --adapter-kwargs '{}'

3 · Review and attest

Complete the generated family review records against the actual evidence. Each review-bearing family declares the minimum relationship it needs: HUMAN, ROLE_SEPARATED, or THIRD_PARTY. A human review may complete a technical PASS; it can never override FAIL, ERROR, NOT_TESTED, or INCONCLUSIVE.

asimov assessment-status ./assessment

After a HYBRID / REVIEW_REQUIRED family judgment is complete, the reviewer signs that exact record with their own authenticated identity:

asimov sign-review ./assessment/reviews/requirements/ACC-006.json \
  --provider google \
  --identity reviewer@example.org

asimov verify-review ./assessment/reviews/requirements/ACC-006.json

ROLE_SEPARATED may be internal but must be outside the implementation/control-owner role. THIRD_PARTY requires a separate legal entity from the Assessment Subject plus a signed independence declaration. Assessment preconditions remain structured and package-bound but are not individually attested in 0.2.

Review attestation guide →

4 · Finalize

Fail-closed finalization merges technical and human evidence, requires the companion attestation for every relied-upon family review, renders the report, and builds the evidence manifest and verification statement.

asimov finalize-assessment ./assessment

5 · Verify

A1+ requires trusted evidence integrity outside the actor's unauthorized mutation authority. A4 additionally requires authenticated package signing and an external checkpoint. A5 additionally requires third-party assessment by a separate legal entity, durable external retention/escrow, and fresh-environment reverification.

asimov verify-package checks the package signer and every relied-upon family review attestation locally with Cosign. Follow the generated VERIFICATION-INSTRUCTIONS.md exactly.
