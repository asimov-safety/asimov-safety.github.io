Studio.

The same Asimov engine and portable assessment files, without hand-editing JSON and Markdown. Studio runs on your computer and opens in your browser.

Why Studio exists

The standard should be rigorous. Using it should not be painful.

One engine, two interfaces

No new assessment format.

Studio is a convenience layer.

It creates and edits the same Asimov workspace used by the CLI. Open a CLI-created assessment in Studio, or continue a Studio-created assessment from the command line.

The standard is still language-neutral.

Asimov Core does not require Python. The current reference implementation and Studio require Python 3.10+, but another conforming implementation can be written in any language.

Launch

One command.

Install the open-source reference implementation, then start Studio. It binds only to your own computer and chooses an available local port automatically.

python3 -m pip install "https://github.com/asimov-safety/asimov/archive/refs/heads/main.zip"

asimov studio

Windows PowerShell can use py -m pip for installation. Studio also accepts asimov ui as an alias.

Guided workflow

From scope to signed report.

Workspace

Create or reopen an assessment, choose the assurance level, identify the assessor and organizations, and connect the deployment adapter.

Scope & readiness

Describe what is actually being tested, the threat model, and exclusions. Studio then runs the same fail-closed readiness diagnostics as asimov doctor.

Technical test

Acknowledge the human obligations and run the same technical probe engine used by the CLI. Missing control surfaces remain blockers, not partial credit.

Human review

Complete HUMAN, ROLE_SEPARATED, and THIRD_PARTY reviews through structured forms instead of raw JSON. Required family judgments can be signed with the reviewer’s Sigstore identity.

Finalize & verify

Build the report and evidence package, sign the public report, and verify the complete package—including relied-upon review attestations—locally.

Your assessment stays portable, local, and inspectable.

Local-first by design

Not another account.

No Asimov cloud required.

Studio binds to 127.0.0.1, uses a fresh session token on every launch, enables no cross-origin API access, and stores no Studio account or cloud-side assessment state.

Your adapter stays yours.

Adapter settings entered in Studio are kept only for the browser session. They are not written into the assessment package, which helps keep credentials and runtime configuration out of portable evidence artifacts.
