Upload an Asimov report and get plain answers: Has it been changed? Who signed it? Which assessment does it belong to? The technical cryptography stays out of the way unless you want to inspect it.

Verify a report ↓
One-file public check

Upload the report.

You only need the HTML report. Nothing from the private evidence package is uploaded.

For a signed report, the definitive signer check is: asimov verify-report report.html
Confirm the signature yourself

Run the signer check on your own computer.

asimov verify-report is the independent signature check. It reads the signature already embedded in the HTML report, asks the official Cosign verifier to validate it, and tells you whether the named signing account really signed that exact assessment record. Your report is checked locally; it is not uploaded anywhere.

1 · Install Asimov

Requires Python 3.10 or newer.

macOS / Linux
python3 -m pip install "https://github.com/asimov-safety/asimov/archive/refs/heads/main.zip"
asimov --help
Windows PowerShell
py -m pip install "https://github.com/asimov-safety/asimov/archive/refs/heads/main.zip"
asimov --help
2 · Install Cosign

Cosign is the official Sigstore command-line verifier that performs the cryptographic signature check. Use the platform instructions in the Cosign installation section below, or the official Sigstore installation guide ↗.

3 · Verify the report

Save the HTML report anywhere on your computer, open Terminal / PowerShell in that folder, and run:

asimov verify-report report.html

A successful signed-report check reports that the report content is unchanged and identifies the verified signing account. If the signature does not match the embedded signing identity, verification fails.

What this does NOT proveA valid signature does not prove the assessment was correct or that the system is safe. It proves which report was signed, and by whom when signer verification succeeds.
01

Has the report changed?

Asimov records a digital fingerprint when the report is issued. If someone later edits the findings, result, assessor, or other report content, that fingerprint no longer matches.

02

Who signed it?

A signed report can include proof that a specific account signed the assessment record. When that signature is independently checked, Asimov can show the verified signer instead of trusting a name typed into the report.

03

Can the signing record be rewritten later?

Sigstore includes public, time-stamped signing information so the signer cannot quietly replace the old signing record with a different one later.

04

Does “verified” mean “safe”?

No. Verification tells you whether this is the original report and, when the signature is checked, who signed it. The report itself still tells you what passed, failed, was not tested, or required human judgment.

Publishing an Asimov report?

Sign it in one command.

Signing is what lets a public reader answer the plain-language question “Who signed this?” rather than merely checking that the report and its embedded record agree.

Install Cosign once

Asimov uses Sigstore’s Cosign tool to create and check signatures. Choose your platform:

macOS
brew install cosign
cosign version
Windows

Download the latest cosign-windows-amd64.exe (or the build for your architecture) from the official Cosign releases page, rename it to cosign.exe, and place it in a folder on your PATH.

cosign version
Linux

Homebrew/Linuxbrew works, or install the official binary/package for your distribution and architecture. For Linuxbrew:

brew install cosign
cosign version

If Go 1.20+ is already installed, this works on macOS, Windows, or Linux:

go install github.com/sigstore/cosign/v3/cmd/cosign@latest

Official Cosign installation guide ↗ Cosign releases ↗

Sign the finalized report

The simplest human flow is to use the same Google account/email you want readers to see as the authenticated signer:

asimov sign-report report.html \
  --statement asimov-statement.json \
  --provider google \
  --identity you@example.com

When Cosign opens the authentication flow, sign in as that exact account. Asimov creates the Sigstore bundle and embeds the authenticated verification capsule back into report.html.

Publish the report

That’s it. Publish or send report.html. A reader uploads that one file here and sees the report integrity, assessment binding, and—when the Sigstore verification succeeds—who signed it.

Other supported identity providers include GitHub, Microsoft, GitHub Actions, and custom OIDC issuers. The CLI will fail verification later if the identity used to sign does not match the identity you declared.

A signature answers one question: Who signed this report? It does not answer whether the assessment was correct or whether the signer was independent.
